二

阶段详解 · L2 vs L3

L2 当前 人机协同 · 7 步

  1. 品鉴检测 — 人工输入底线规则，AI 评测；观澜、清流独立运行
  2. 误判筛查 — 人工复核，剔除误判案例
  3. 问题归因 — 人工分类，手动观澜定位
  4. 策略制定 — 观澜报告辅助，人工决定优化或新发
  5. 配置实验 — 人工配置 AB 参数
  6. 数据分析 — 人工回收指标
  7. 决策推全 — 人工判断推全时机

L3 目标 AI 自主决策 · 6 步

  1. 品鉴检测 — 自动巡检、双模型误判筛查、标签前置判断、发现即建台账
  2. 观澜归因 — 输出处置结论，决定打标/修配置/需新策略
  3. 策略制定 — 自动生成过滤/降权方案与实验设计
  4. 云河验证 — 镜像 QA，验证通过才进实验
  5. AB 实验 — 自动建实验，小流量观察 ≥3 天
  6. 上线发布 — 达标推全，误伤回滚，案例闭环

L3 各阶段职责

① 品鉴检测

  • 只做「发现问题」，聚焦高曝光低质案例挖掘
  • 输出标签 + weighttype 标识（保留原标签字段）
  • 底线标准分类型定义 weight，与三级标签 1:N 映射
  • 标签四态前置：有标签 / 库有未打 / 无标签
  • 双大模型评估，聚类、定级、影响面排序

② 观澜归因

  • 承接品鉴 / 相似召回分流后的案例
  • 通过 weighttype → 查 tag 映射 → 复用线上策略
  • 有标签仍曝光 → 配置缺陷 vs 需调参/新策略
  • 无标签 → 相似召回打 weighttype 后再走策略

③ 策略制定

  • 按影响面与风险级别自动生成策略方案
  • 重排层：过滤 / 降权 / 打散 + 参数系数
  • 含完整实验设计（流量、观察期、扩量计划）

④ 云河验证 · ⑤ AB · ⑥ 发布

  • 云河：方案 → 配置落地 → 镜像功能验证 → 飞书确认
  • AB：镜像通过后自动建实验，5% 起量，观察 ≥3 天
  • 发布：达标扩量推全，误伤回滚，更新案例台账

验证与实验 · 关键原则

两层验证，不可混：④ 镜像验证 = 进 AB 前的配置检查（镜像不过 = 绝不进 AB）；⑤ AB 实验 = 小流量后的效果验证（不达标 ≠ 失败，分型路由）。
阶段典型情况处理方式
镜像配置缺陷 / 未生效云河修配置 → 重跑镜像
镜像方案不可落地回 ③ 策略制定
镜像重复失败 ≥ 2 次飞书升级人工
AB达标（低质率降 + 无误伤）按扩量计划推全
AB效果不足 / 归因存疑调参回 ③ 或回 ② 观澜（≤2 轮）
AB误伤 > 0 / 指标恶化停实验 + 回滚配置

相似召回 Agent · Case 与卡点

一、Case 示例：站内营销（机票类）

典型无标签 case：T 站「机票类营销笔记」——封面/标题强营销感（如 "DIRECT ✈️ to Chongqing only RM812"），线上无对应三级标签，无法直接配策略。探查详见 Embedding 相似召回探查报告。
探查结论（人工抽检）阈值 ≥0.82阈值 ≥0.84
宽口径（封面+标题营销感）94 条候选，准确率 85.1%30 条，准确率 100%
窄口径（正文也为站内营销）准确率仅 49.5%，不能裸用样本过少，不推荐
主要误伤35 条「宽是窄否」——标题像营销，正文实为攻略/资讯

L2 当前流程

  1. 人工发现 — 人工刷高曝光池，识别机票营销感内容
  2. 无标签卡点 — 标签库无覆盖，无法直接配策略
  3. 人工抽样 — 凭经验找相似内容，定降权范围
  4. 策略制定 — 人工配召回层/重排层策略
  5. 配置实验 → 推全 — 全程人工，3–5 天/类

L3 目标流程

  1. 品鉴检测 — 识别「机票类营销」，输出 weighttype（无存量标签）
  2. 相似召回 Agent — 9 条 seed → 文本 embedding KNN → 大模型分档位（0.8/0.85/0.9）抽检定阈值
  3. 打 weighttype — Recall 内容打 weighttype 标识，代替逐条打三级标签
  4. 观澜归因 — weighttype 查映射 → 复用/新建策略方案
  5. 云河验证 → AB → 推全 — 镜像先验，小流量观察，案例闭环

二、核心价值 · 最大效果影响点

最大效果影响点

内容识别 → 相似召回是 badcase 率 10%→2% 的关键瓶颈。大量新问题（如站内营销）线上无三级标签，传统路径等内容理解建标签 + 人工打标周期太长；通过 embedding 召回同类内容、打 weighttype 代替打标，才能快速扩大治理覆盖面。

embedding 召回 + weighttype 标识，代替逐条打三级标签。对于线上无标签的新问题类型（如机票类营销），不需要等内容理解团队新建标签，而是通过向量召回同类内容 → 打 weighttype → 观澜复用映射标签的线上策略，大幅缩短从发现到治理的周期。

三、自动化调阈值流程

目标：让大模型实现 embedding 阈值设定 + 召回准确率评测，形成自动化流程（参考 探查报告）。

步骤做什么说明
① 向量召回 seed case 文本 embedding → KNN TopN → 业务过滤（站点/locale） 标题+正文转向量，全站统一索引后过滤
② 分档位阈值 分别用 score ≥ 0.80 / 0.85 / 0.90 三档回捞 对比各档位命中量级
③ 分段抽检 大模型对各档位抽样判断是否为 target badcase 量级大 → 分段抽检；量级小 → 可全量抽检
④ 选阈值 取准确率达标且召回量合理的档位 探查示例：宽口径 ≥0.84 准确率 100%（30 条）
⑤ 打 weighttype 用选定阈值回捞全量 → 内容打 weighttype 标识 代替逐条打三级标签，进入观澜策略链路
⑥ 人工确认 必过卡点 人工确认最终阈值与 weighttype 范围 大模型推荐阈值，人工做最终决策

四、当前卡点

必有误伤，阈值不能全自动 分段抽检只能估算准确率，无法消除误伤（探查：35 条「宽是窄否」——标题像营销、正文是攻略）。最终阈值必须人工确认，这是当前设计的硬卡点。
治理口径决定阈值可用性 宽口径（封面+标题营销感）≥0.84 准确率 100%；窄口径（正文站内营销）0.82 仅 49.5%。口径不定，阈值无意义。
召回量级 vs 评测成本 阈值降低（如 ≥0.75）可召回 2600+ 条，无法全量评测。只能分段抽检 → 准确率是估计值，不是精确值。
图片 embedding 未就绪 一期仅文本路径（标题+正文）；封面类相似一期不可用，xx/xx 后补充。
一句话：相似召回 Agent 的价值是「无标签也能治理」——用 weighttype 桥接 embedding 召回与存量策略；卡点是大模型能推荐阈值，但误伤不可避免，人工确认不可省。
